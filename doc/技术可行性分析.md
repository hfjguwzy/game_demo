# 《海王遗孤》技术可行性分析

日期：2026-11-02  
决定：游戏用 WebGAL 4.6.6 做。本机编辑器在 `d:\tools\WebGAL_Terre_Windows_4.6.6\release`。

宣传页 `index.html` 继续单独放着。游戏只做 PC。安装后的总体积以 100GB 为上限，前期先不按这个体积做。

## 结论

`demo-desktop` 那套 Vue 2 + Express + SQLite + Element UI 不进入游戏。WebGAL 自己包含编辑器、剧本播放和 Windows 导出。

现在这份下载是编辑器的发行包，不是引擎源码。入口是：

`d:\tools\WebGAL_Terre_Windows_4.6.6\release\WebGAL_Terre.exe`

双击它。编辑器会在浏览器里打开，文档中的地址是 `http://localhost:3001`。不要直接双击 `public\index.html`，那个页面没有后面的编辑器服务，单独打开不能用。

游戏工程在 `terre-data\games` 里，见下文「游戏放在哪个目录」。不要在 `d:\tools` 的模板上直接改剧本，模板升级时会被覆盖。

## 本机这个目录里有什么

`release` 下面没有 `package.json`、没有 `src`，因为作者已经把编辑器打成了一个程序。

| 路径 | 作用 |
| --- | --- |
| `WebGAL_Terre.exe` | 编辑器入口。约 64MB，是打包后的 Node.js 程序 |
| `public\index.html` | 编辑器页面，由上面的 exe 提供。页面挂在 `<div id="root">`，脚本是压缩后的 React |
| `public\games` | 4.6 之前的旧位置。现在是空的，编辑器不从这里认游戏 |
| `Exported_Games` | 安装目录里的空目录。实际导出结果在用户数据目录里 |
| `assets\templates\WebGAL_Template` | 游戏引擎的成品。入口是这里的 `index.html`，逻辑在 `assets\index-*.js` |
| `assets\templates\WebGAL_Electron_Template` | 导出 Windows 时用的 Electron 壳，可读的入口是 `resources\app\main.js` |
| `assets\templates\WebGAL_Android_Template` | Android 导出模板。这部游戏用不到 |
| `lib` | 编辑器自带的小工具，不是游戏入口 |

所以「release 里看不到入口」是因为入口是 `WebGAL_Terre.exe`，不是一份待 `npm start` 的源码。

## WebGAL 用什么语言

要分开看。写游戏和改引擎不是同一种语言。

| 部分 | 语言 | 你现在这份里的形态 |
| --- | --- | --- |
| 剧本 | WebGAL 脚本。一种给视觉小说用的文本指令，例如 `playVideo:OP.mp4;` | 建好游戏后出现在 `game\scene` |
| 游戏引擎 | TypeScript。界面用 React，画面用 PixiJS 6。用 Vite 打包 | `WebGAL_Template` 里只有打包结果，没有 `.ts` |
| 编辑器页面 | TypeScript，界面用 React，用 Vite 打包 | `public\assets\index-*.js` 是压缩后的脚本 |
| 编辑器程序 | Node.js。打进 `WebGAL_Terre.exe` | 没有 `.js` 源文件可以打开 |
| Windows 游戏外壳 | JavaScript。Electron | `WebGAL_Electron_Template\resources\app\main.js` 可以直接读 |

你写《海王遗孤》时面对的是 WebGAL 脚本，加上图片、音频、视频文件。不需要先写 TypeScript，也不需要 Express 或 SQLite。

## 游戏放在哪个目录

Terre 4.6.6 只认「用户数据目录」下面的 `games`。没有单独一项把某个文件夹指成游戏工程。`D:\Project\game_demo` 根目录里已经有宣传页、文档和 git，不能整个当成用户数据目录，编辑器会因为目标里已有文件而拒绝迁移。

用户数据目录已经迁到：

`D:\Project\game_demo\terre-data`

当前这款游戏在：

`D:\Project\game_demo\terre-data\games\新的游戏`

`C:\Users\21088\.webgal_terre\config.json` 里的 `userDataPath` 指向上面的 `terre-data`。配置文件本身仍留在 `C:\Users\21088\.webgal_terre`。原来的 `C:\Users\21088\.webgal_terre\games` 已经空了，文件都在仓库里。

编辑器若还开着，刷新页面后再看游戏列表。设置里的「用户数据」可以再迁移，或「恢复默认目录」迁回用户主目录。便携模式是在安装目录下建 `data` 文件夹；开着时不能再用「迁移到此目录」。

官方说明：<https://docs.openwebgal.com/migration.html>

## 和原来的桌面技术栈

`d:\Project\demo-desktop` 仍是后管模板：Electron 19、Vue 2、Element UI、本机 Express `127.0.0.1:17777`、加密 SQLite。那些不复制进 `game_demo`。

WebGAL 导出 Windows 时，用的是它自己的 Electron 模板，不是 `demo-desktop`。你已有的 NSIS 经验只在一件事上还有用：导出的结果如果只是一个目录，而你要一个安装向导，再用当前稳定版的 electron-builder 去包那个结果。不要把 Express 和数据库加回去。

## 体积和安装包

100GB 是安装之后的上限。前期资源很少，用 Terre 导出 Windows 即可。

视频变多以后，注意三件事：

1. 不要把视频打进 asar。electron-builder 拒绝超过 `4294967295` 字节约 4.2GB 的单个文件。
2. electron-builder 默认的 NSIS 安装包大约到 2GB。再大，构建会失败，或者装不上。一个 100GB 的 `setup.exe` 不是目标。
3. mp4、webm、mkv 已经压过，打进安装包几乎不会再变小，只会让打包和安装变慢。

体积上来之后，程序和剧本可以仍是一个小的导出结果，视频放在旁边的内容目录，从磁盘播放。单条视频先保持在 4GB 以下。播放用引擎自己的 `playVideo`，不要读进内存，也不要放进数据库。

## 现在先不做

- 不把 `demo-desktop` 复制进来当游戏骨架
- 不在 `d:\tools\WebGAL_Terre_Windows_4.6.6` 的模板里改剧本
- 引擎源码以后要改时再克隆 `OpenWebGAL/WebGAL`。当前这份 `release` 里没有可编辑的 TypeScript
- 不为手机改游戏。宣传页的移动端也先不动
- 不把尚不存在的视频打进安装包
